Support and abuse reporting

Dream Wi-Fi is a standalone prototype. Before reporting an issue, note the device model, Android version, app version, approximate time (UTC if possible), and what you expected versus what happened. Never include passwords, source tokens, pairing codes, access tokens, exact home coordinates, or private network details.

Public tracker warning: GitHub issues are public. Do not publish private or security-sensitive details there. If you need to report a vulnerability or disclose personal information, use a private channel through the maintainer's GitHub profile rather than opening a public issue.

General support

Open a ticket at Dream Wi-Fi GitHub Issues. Include redacted error messages and steps to reproduce. Do not upload logs unless secrets and personal information have been removed.

Report abuse or unauthorized sharing

Provide the date/time, a concise description, and any non-sensitive evidence. Do not try to access the source owner's router, accounts, or devices. The operator may disable a source or revoke receiver sessions while investigating.

Known limitations

  • A map listing does not mean a network is available or authorized to use.
  • A source-side internet probe is not proof of successful receiver browsing.
  • Background/Doze reliability, traffic-leak prevention, and broad native VPN compatibility require physical-device testing.
  • Third-device internet through the receiver phone's hotspot is not implemented or verified.
